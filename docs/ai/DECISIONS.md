# Decisions
- 2026-10-15: Branch `codex/frontend-modernisation`, worktree `/home/chassapis/starlights-frontend`, base `6a6aea2`. Local repository is authoritative; no pull/reset/stash.
- Keep server registration/eligibility, edition rules, snapshots, spellcasting and combat functions intact. Presentation consumes them, so multiclass and existing characters keep their semantics.
- Preserve `/characters/:id/sheet` for Aurora PDF; add a separate interactive route using the same APIs. Existing bookmarks/exports remain valid.
- Use semantic theme variables with existing localStorage key; no new UI framework or separate theme implementations.
- Use inline spell cards with explicit actions, descriptions, filters and pagination. Avoid hover-only essentials and nested scroll panes.
- Documentation is a routing map, not a source copy. Skills point to shared docs instead of repeating architecture.
- Preserve supplied branding through deterministic browser-canvas crops/resizing. Keep navy framing instead of removing the original background or redrawing the emblem. No image-processing dependency added.
- Keep interactive-sheet expansion state above conditional loading views so preparation-related query refreshes preserve navigation. Use Radix DialogTrigger to restore focus after theme previews.
- Validate real state in a disposable SQL database with read-only content imports and synthetic characters; never copy production characters to improve test coverage. Distinguish fixture screenshots from real-backend workflows and report missing content explicitly.
- 2026-10-21 (visual fidelity, branch `feature/visual-fidelity`): the owner's three-theme dashboard mockup is the layout target. Slate becomes a dark slate-blue theme like the mockup (the Slate artwork is pale silver made for it); `isDarkTheme` = Midnight or Slate. One frame (`StarfallShell`) around header, page and footer replaces the corners floating in the margins; its corners and edges are placed from the SVGs' own geometry so they sit on the border line. The 512 × 870 portraits are no longer the hero (kept in `public/branding/starfall/`); the hero is the supplied D20 emblem over a live wordmark in the existing font (no new font dependency).
- 2026-10-21 (polish mission, stage 1 `feature/polish-brand-responsive`): the homepage D20 looked warped because the supplied SVG drew a 98 × 148 hexagon 10 units above the compass centre with non-icosahedron inner lines (CSS was square). `tools/frontend/d20-emblem.mjs` redraws only the die as a true icosahedron seen onto one face (regular hexagon, front face on radius R/φ, 10 visible faces) and keeps each theme's gradients and the compass as supplied. Favicons, the iOS icon and the navigation emblem use the owner's home-screen kit (`public/icons`, copied unchanged; 16/48px and `.ico` are plain resizes of its 1024px source): a painted raster for small sizes and launchers, while the hero keeps the theme-coloured vector emblem. Large monitors get two breakpoints (`3xl` 2000px, `4xl` 2560px), one type step (17px from 2400 × 1250, 20px from 3200 × 1800; ultrawide 1440p stays at 17px), wider frame caps and wider tool-page containers; prose and form widths keep their line lengths. 1920 × 1080 and smaller are unchanged.
- 2026-10-21 (polish stage 2 `feature/polish-ornament`): richer ornament through shared rules, not page hacks: every page title and Lore/book heading gets the supplied section marker; panel corners only on hero, list-header, session and sheet-header panels (one corner where panels sit in rows); one celestial divider on the home page; the celestial accent on empty states; one botanical sprig on the campaign overview; the book page gets a fine inner rule. `celestial-accent` and `botanical-sprig-optional` from the universal pack are now installed (byte-identical); `shooting-star-optional` is not used. Battle, encounter, tables and dense forms deliberately stay plain.
- 2026-10-21 (polish stage 3 `feature/polish-units`): Imperial/Metric is a per-browser display preference (`starfall-units`, default Imperial) like the theme, in the same dialog, applied at once; no database or API change. Canonical values stay feet and pounds everywhere (rules, battle model, saved data, PDF, Aurora files): conversion happens only where a component renders a structured number or a short rules label, with the D&D table factors (5 ft = 1.5 m, 1 lb = 0.5 kg, 1 mile = 1.5 km) so grids stay in half metres and inputs round-trip exactly. Rules prose and free-text fields are not converted (unreliable). The printed/PDF sheet stays Imperial: Aurora's template and the comparison scripts read its fields.
